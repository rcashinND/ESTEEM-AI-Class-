# Two-minute demonstration script

**0:00–0:20 — Problem.** “A self-employed tradesperson often has to interpret vague messages between jobs. Trawd organises an enquiry while keeping the original in view. The tradesperson still makes the decision.”

**0:20–0:35 — Feedback and honest capability.** “Reviewers liked the summaries and uncertainty handling, but the repository paths were inconsistent and the public demo was old. This is a simulated prototype: three prepared examples and limited rules, not a live AI model.”

**0:35–1:00 — Plumbing example.** Click Clear job, then Analyse Enquiry. “The summary retains South Bend, next Tuesday and the purchased replacement tap. Urgency is not invented, and follow-up questions remain visible.” Mark reviewed. Change Tuesday to Wednesday, analyse again. “This now uses the explicitly labelled rules, keeps Wednesday and resets review.”

**1:00–1:25 — Uncertainty.** Click Multiple trades and analyse. “The cause is unconfirmed. An electrician and possibly other trades may need to assess it. The electrical warning remains, and photos are local previews only—not a diagnosis.”

**1:25–1:40 — Validation.** Clear and analyse empty input. “There is a useful error rather than an old summary.” Optionally show Vague enquiry: “Missing trade, location and timing remain unknown.”

**1:40–2:00 — Evidence and limits.** “The automated logic and HTTP tests pass, and the fresh-copy check installs, tests, starts and loads every asset. The evidence report distinguishes browser and automated checks. Rules still have narrow coverage; there is no proof yet of time saved in practice.” State the actual public release status from the checklist; never say it is updated unless rechecked.
