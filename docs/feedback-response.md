# Response to reviewer feedback

Source: two anonymous classmate reviews (October 30 and November 2) and Emelia Hughes’s November 11 feedback on the original Canvas MVP. The comments describe the reviewed build. See [current testing evidence](testing-evidence.md) for later checks.

| Feedback | Decision | Response and evidence |
|---|---|---|
| Both classmates hit “Unable to open Trawd” during local startup. The first also saw tests fail because the repository put files at root while the commands expected `public/` and `tests/`. | Acted on | Align directories, retain the lockfile, and check HTTP assets plus `npm install`, `npm test` and `npm start` from a clean copy. The [fresh GitHub baseline run](evidence/current/github-baseline-clean.txt) reproduces the corrected startup path. |
| The first classmate changed Tuesday to Wednesday and got the generic fallback. The second found that the edited location required manual review. Both found prepared details useful. | Acted on | Add bounded recognition of explicit weekday and place phrases without reusing fixture facts. The [same-input replay](evidence/current/before-after-weekday.json) shows the earlier fallback and the later accurate Wednesday field and action-oriented follow-ups. Free-form language beyond supported patterns can still require manual review. |
| The clear plumbing case had follow-up questions the tradesperson could act on. Both peers valued tentative multi-trade handling, and the first highlighted the socket caution. | Acted on | Preserve questions about availability, compatibility and leak severity. Keep electrical cautions and multiple candidate trades visible while withholding an unconfirmed cause. |
| Emelia liked checking the original next to the summary. In the vague case, she valued that the prototype left trade, location and timing unconfirmed. | Adapted | Give the tradesperson a short brief and keep corrections on the intake page. Ask the customer for missing information and retain unknowns in the brief for follow-up. The trade-off is reduced source traceability on the review screen. |
| Emelia and classmates warned that the linked deployment lagged the code. Emelia noted the older site incorrectly labelled results as AI-generated. | Acted on | Make prepared, rule-based and manual-review modes explicit. Verify the live build separately from source and record the result in the [release evidence](testing-evidence.md). |
| A live model or unrestricted interpretation could reduce fallbacks, but no reviewer established the accuracy of such a change. | Deferred | Keep a bounded prototype so its errors can be reproduced and the current workflow can be evaluated. Improve the evaluation set before considering model integration. |
